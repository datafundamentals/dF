# Ticket 0525c - Agent-Controlled Session Titling

## Executive Summary

Currently, "Cathy" (the OpenClaw agent) has no way to name or rename the work request session. Sessions often remain "Untitled" until they are accepted, and even then, the title is generated by a rigid backend heuristic. 

This ticket implements a "Command Protocol" that allows the agent to set or update the session title at any time by including a specific marker in its response. The backend trigger `onOpenclawMessage` will detect this marker, update the Firestore document's `title` field, and remove the marker before the message is saved to the UI.

---

## Functional Requirements

### 1. Protocol Definition
The agent shall use the following pattern anywhere in its response to signal a title change:
`[SET_TITLE: Your New Title Here]`

### 2. System Context Update (@services/functions)
Update the `systemContext` generation in [services/functions/src/triggers/onOpenclawMessage.ts](services/functions/src/triggers/onOpenclawMessage.ts) to instruct the agent on how to use the protocol.
- **Instruction:** "If you identify a concise and descriptive title for this session, or if the session is currently 'Untitled', please include `[SET_TITLE: Concise Title]` in your response. You may update this title at any time if the conversation context shifts."

### 3. Parsing & Extraction Logic (@services/functions)
Modify the `onOpenclawMessage.ts` trigger after the OpenClaw API returns a response:
- **Regex Check:** Scan the assistant's reply for the `\[SET_TITLE:\s*(.*?)\]` pattern.
- **Metadata Update:** If found, capture the title and add it to the `conversationUpdate` object. This should overwrite any existing title.
- **Fallback Preservation:** Keep the existing `buildConversationTitle` logic only as a final fallback for when a session is accepted without an agent-provided title.

### 4. Content Sanitization (@services/functions)
- **Scrubbing:** Before saving the assistant's message to the `messages` subcollection, remove the `[SET_TITLE: ...]` marker and any surrounding excessive whitespace. 
- **User Privacy:** The user should never see the `[SET_TITLE]` tag in the chat UI.

### 5. Surface Current Title in System Context (@services/functions)
In `onOpenclawMessage.ts`, include the current title in the `baseSystemContent` string before it is sent to OpenClaw.
- **New String:** `CONTEXT: The unique ID for this work request is ${requestId}. Status URL: ${statusUrl}. Current Session Title: ${currentTitle || 'Untitled'}`

---

## Implementation Details (Trigger Logic)

```typescript
// Proposed logic flow in onOpenclawMessage.ts
const currentTitle = conversationSnap.get('title');
const baseSystemContent = `CONTEXT: The unique ID for this work request is ${requestId}. Status URL: ${statusUrl}. Current Session Title: ${currentTitle || 'Untitled'}`;
// ...
const rawAssistantContent = result.choices?.[0]?.message?.content ?? '';
let finalAssistantContent = rawAssistantContent;

const titleMatch = rawAssistantContent.match(/\[SET_TITLE:\s*(.*?)\]/);
if (titleMatch) {
  const customTitle = titleMatch[1].trim();
  if (customTitle) {
    conversationUpdate.title = customTitle;
  }
  // Remove the tag from the content saved to the database
  finalAssistantContent = rawAssistantContent.replace(/\[SET_TITLE:.*?\]/g, '').trim();
}
```

## Acceptance Criteria

1. If Cathy includes `[SET_TITLE: Designing a Spaceship]` in her reply, the Firestore document title is updated to "Designing a Spaceship".
2. The `[SET_TITLE: ...]` tag does not appear in the message visible in the chat UI.
3. The current session title is passed to the agent in the system context on every message.
4. The agent can change the title multiple times throughout a session.
5. If no tag is provided, the existing acceptance-based titling fallback still works as a safety net.
6. `pnpm build` in `services/functions/` completes without errors.
