✅ Canonical Firebase Pattern

Production Google Sign-In + Emulator-Based Features

COPY THIS PATTERN FOR ALL APPS

⚠️ Production Firebase Required

Google Sign-In requires production Firebase credentials. The emulator placeholder values in .env.emulator won't work.

To use this demo, create .env.local with your real Firebase project credentials:

  • Copy .env.production.example to .env.local
  • Fill in your actual Firebase config from Firebase Console
  • Set VITE_USE_EMULATOR=false (for auth only - other services use emulators)
  • Restart the dev server: pnpm dev

Note: .env.local overrides .env.development and is gitignored (safe for real credentials).

🎯 What Makes This Canonical?

This demo shows the recommended architecture for all apps in the DF monorepo. It combines production-ready authentication with fast local development using Firebase emulators.

  • Production Google Sign-In: Uses df-auth-wrapper with real Firebase Auth (no emulator)
  • Emulator-Based Features: Firestore, Storage, and Functions run on local emulators for fast iteration
  • Clean Separation: Auth wrapper handles authentication, other features slot inside
  • Reusable Pattern: Every app should follow this architecture - minimizes differentiation

Key Principle: Any auth implementation that doesn't use df-auth-wrapper is considered an anti-pattern in our monorepo.

🔐 Protected Firebase Features

You're now authenticated with Google. All the features below are protected by df-auth-wrapper and run on Firebase emulators for fast development.

💡 Why This Architecture?

  • Fast Development: Emulators start instantly, no cloud latency
  • Real Auth Testing: Test actual Google OAuth flow during development
  • Consistent Patterns: Same auth wrapper across all apps = less cognitive load
  • Production-Ready: Same auth code works in dev and production

⚠️ Anti-Pattern Warning

Do NOT use the emulator auth UI pattern from the old demos. While it's cute and proves emulator auth is possible, it creates unnecessary differentiation between apps. Always use df-auth-wrapper for production-ready authentication.
